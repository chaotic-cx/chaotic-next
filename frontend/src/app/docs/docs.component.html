If a bug is present in a package, please report it to our bug tracker or comment on AUR first.
After confirming that the issue is not a packaging issue, you can report it to the upstream project.
Do not report it upstream without verifying this first.
This ultimately increases the chances of the bug being fixed faster and more efficiently.

You can always report build failures or broken packages via our GitHub repository by creating a new issue.

Our main repository is the one on GitLab as the build system makes extensive use of its CI pipelines.

If you would like to see a new package added to Chaotic-AUR, please submit a new issue via our GitHub repository. Issues on GitLab are more likely to be ignored. We prefer for historical reasons.


Before submitting the request, ensure searching for existing issues concerning the same package.
We might have been dealing with it already in the past or removed it for a reason.


Also, check whether the license permits distributing the software, as well as it not being part of our ban list.

Chaotic-AUR exposes a public JSON API so you can query packages, builds, metrics and repository state programmatically. Browse the interactive API documentation for the full list of endpoints and schemas.

When an AUR package gets updated and the update is anything else but a minor version change, our build system prepares the update by opening a merge request (MR) on GitLab against the pkgbuilds repository.

Each MR then goes through a human review: maintainers inspect the diff, build the package and verify it links against the correct libraries before approving it. Only after a human approves the MR is it merged and the new binary deployed to the repository.

You can follow and act on these pending updates on the Update review page.

For deeper insight concerning our build system, you may consult the Chaotic Manager documentation.
